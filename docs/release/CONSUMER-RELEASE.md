## Install and use

1. Install the testing APK and open TEMPER. Tap ON. First use opens guided setup: read/check the automatic-analysis disclosure, download the public 125 MB model if needed, grant display-over-apps permission and enable TEMPER in Android Accessibility settings. Return after each Android permission; the next missing step is shown. Existing selected-chat consent does not automatically grant the new mode.
2. After setup, tap ON once and use supported chats normally. TEMPER automatically analyzes the current verified visible WhatsApp chat and resets context when switching chats. There is no per-chat start or one-minute expiry. Other apps can show the companion without estimates.
3. Drag the companion to move it; tap to toggle its compact panel. Keyboard/panel changes keep power ON; unreadable layouts show no scores and recover when supported text returns.
4. Tap OFF on the home screen or notification to remove all companions and stop capture. Closing TEMPER's task or losing its foreground companion also stops it. A cold process start defaults OFF; stored consent/model/permissions are retained for the next ON tap. Avatar selection and detailed permissions/ratings are secondary actions. Revocation remains in Settings → Set up and permissions.

The general floating character can appear across ordinary apps without reading their contents. Sensitive Android screens and apps may suppress overlays. Automatic analysis supports only the observed WhatsApp 2.26.37.73 portrait layout (version code 263707322), at least three complete plain-text turns with both sent and received roles. Documents, quotes, reactions, clipped or ambiguous rows fail closed. Telegram, Instagram and other layouts require device fixtures and verified adapters before automatic estimates can be advertised. Both companions are draggable. A moved analysis companion stays within the visible chat area above the composer; keyboard changes clamp its position temporarily and restore the preferred position when space returns.

The on-phone INT8 GoEmotions model is English-trained. Hinglish and sarcasm remain unreliable. Independent bars need not sum to 100%. The latest remote turn supplies the spectrum; the previous remote turn supplies a conservative tension-change proxy. Local-speaker emotion does not contaminate remote scores. Concern uses fear/nervousness; caring alone is excluded to avoid labeling reassurance as distress. This smaller on-phone engine does not reproduce the legacy backend's separate sentiment/sarcasm/toxicity classifiers. Direction remains uncertain when evidence is weak. There is no measured TEMPER live-chat accuracy claim.

## Real sales and publishing gates

These steps require the owner's accounts and configuration. A local build cannot create a merchant account or obtain store approval.

1. Create/configure the Google Play developer/merchant account for `dev.temper.android` and enroll Play App Signing. Check the owner is comfortable retaining this application ID before creating the entry.
2. Create three **one-time, non-consumable** products: `temper_avatar_nova`, `temper_avatar_orbit`, `temper_avatar_luma`. Each needs one buy purchase option/offer (no rentals), enabled regions and localized prices. Release first through an internal testing track and add license testers.
3. Grant a dedicated service account the required purchase/order permissions for this app, enable the Android Publisher API and store its JSON in the deployment secret manager. Export the Play licensing public key.
4. Create a separate RSA ≥2048-bit entitlement signing key. Store its PKCS8 private PEM only in the server secret manager; put its Base64 DER public key into `temperEntitlementKey`. Deploy `deployment/store/Dockerfile` from the repository root to an HTTPS service. Cloud Run with minimum instances 0 and a maximum-instance/spend cap is the initial operating-cost choice. Do not mount model weights; this deployment is only for purchases. `StoreBoundaryFilter` exposes only purchase verification and health, limits request bytes and concurrency. Use edge rate limiting and disable request-body and full-URL purchase-token logging. Google API calls use fixed endpoints and no redirects.
5. Build with `temperStoreUrl=https://YOUR_STORE_HOST` and `temperEntitlementKey=BASE64_PUBLIC_KEY`, plus an owner-managed upload keystore via the `TEMPER_KEYSTORE_*` environment variables. Never commit private keys, passwords or service-account JSON. `scripts/build-consumer-release.ps1` verifies the required configuration and builds signed APK/AAB plus lint/tests. Back up the upload keystore securely; Play App Signing should hold the distribution key.
6. Host the privacy policy after finalizing its deployment provider, operational retention and public URL. The owner supplied Luv Tankha, luvtankha06@gmail.com and +91-8178185449 as public publisher/support details. Prepare Data safety, Accessibility declaration and demonstration video, and special-use foreground-service declaration. TEMPER is not an Accessibility tool for disabilities. Review the real data flows, purchase verification and model download against the final forms. Store approval is pending and cannot be guaranteed.
7. Run actual license-test purchases: successful purchase/unlock, cancellation, pending→completed, network loss then restore, reinstall with the same Play account, second device, refund/revocation and acknowledgement failure/retry. Validate physical overlay and keyboard behavior on supported Android/device versions. Only then promote the signed build.

Premium purchase buttons remain disabled without configured verification and Play products. No mock price, debug override, editable ownership boolean or fabricated receipt can grant an entitlement. Play restores query active purchases; the server verifies the signed Play receipt and Google's current purchase/consumption state, then acknowledges non-consumables. It returns a server-signed ownership claim with a 24-hour validity. Offline verified ownership remains available within that interval; refresh is needed afterward. Refunds are checked on restore/revalidation, with an offline revocation delay bounded by claim expiry. No user registration is needed: Play handles buyer identity. Chat data never enters the purchase endpoint.
