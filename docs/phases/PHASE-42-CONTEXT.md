# Phase 42 — Optional analysis ratings and model improvement

1. Objective: let users rate app-generated conversation analysis with separate permission for reviewed visible-context sharing, then provide a reproducible model-upgrade workflow. Users must not be asked to supply emotion labels or analysis.
2. Current repository: clean consumer candidate 0.41.0 at 144a445; developer Play/payments account and production deployment are still pending.
3. Previous work: avatar shop, general overlay, exact WhatsApp adapter, private on-device inference and verified purchase implementation preserved.
4. Verification: phase 41 passed 60 backend tests, seven Android unit tests and native dummy/privacy/overlay checks. Hindi-heavy and sarcasm weaknesses are documented.
5. Architecture: normal analysis stays on-device. New optional contributions use a separate reviewed form and HTTPS endpoint, isolated from Accessibility capture and purchases. Training runs offline; evaluated releases require explicit promotion.
6. Risks: chat excerpts can contain other people's information; user permission alone does not establish the other participant's permission. Model-generated scores are not training truth. No genuine contributed dataset exists yet, so improved accuracy cannot be claimed.
7. Scope: separate consent, bounded visible-session recording, reviewed text/actual estimates plus a 1–5 quality rating, withdrawal/deletion, encrypted server storage with retention, offline export/independent reviewer annotation/training/evaluation, and release documentation. The owner explicitly requested conversation context and clarified that end users only rate quality.
8. Non-goals: silently recording every chat, collecting from users who decline, uploading drafts/contact/history, automatic retraining from model predictions, public datasets, deploying before endpoints/accounts exist, or claiming an upgrade improves accuracy without held-out evidence.
9. Acceptance: declined consent sends nothing; submitted examples have an explicit review/rating/permission step; contributions can be deleted; server/storage limits are enforced; candidate upgrades are reproducible and evaluated without training/test leakage; all app functions remain runnable.
