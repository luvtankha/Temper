# Phase 45 — One-button on/off experience

1. Objective: replace the multi-step everyday activation flow with one prominent ON/OFF control: ON displays the draggable companion and automatically estimates supported visible chats; OFF removes all companions and stops capture.
2. Repository: clean Phase 44 candidate at 7fff82d, version 0.44.0, installed and tested on OnePlus 8T. Current home separates overlay activation, selected-chat setup and one-minute session selection.
3. Completed phases: preserve 00–44 foundations, adapters, on-device model, movable overlay, paid cosmetic picker and optional rated-feedback workflow.
4. Baseline checks: 28 Android JVM tests, native foundation/consumer/generated pipeline/drag checks, successful debug APK and unsigned release AAB, zero lint errors; unchanged backend/model baseline from Phase 43.
5. Architecture: foreground floating companion and Accessibility analysis overlay share one persistent power preference. Existing selected-chat mode remains for developer/explicit feedback workflows. Automatic mode requires a separate one-time disclosure permitting currently visible supported chats, including chat switching, and resets context at conversation boundaries.
6. Risks: Android overlay/Accessibility permissions and model download cannot be bypassed. ON must not silently broaden prior selected-chat consent or optional feedback collection. OFF, revocation and notification stop must invalidate late estimates and remove both overlays. No hidden or unrelated content is read.
7. Scope: simple home power control, guided one-time setup, persistent automatic mode for verified foreground WhatsApp layouts, unified stop state, lifecycle/privacy/one-click regressions, version 0.45.0, build/install/package and updated guides.
8. Non-goals: new adapters, reliable analysis in every messaging app, new models/accuracy claims, automatic chat uploads, enabling Google/Android permissions programmatically, paid deployment or store publishing.
9. Acceptance: once required permissions/model/auto disclosure exist, one tap turns all supported behavior ON and one tap turns it OFF; no per-chat arm/expiry/restart; unreadable layouts wait safely; switching chat clears old results before new body text is analyzed; explicit feedback does not collect across automatic chat switches; model/drag/cosmetic functions remain intact; meaningful generated native checks and builds pass.
