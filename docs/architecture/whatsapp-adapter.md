WhatsAppAdapter first creates a structural read plan. Missing/duplicate header/list/composer, landscape, unknown row types/child IDs, missing timestamps, unexpected sender alignment or missing outgoing evidence fail closed. Rows touching either list edge are excluded. At most the latest eight complete text rows are selected. Remote role requires the calibrated left-aligned body with no outgoing marker; local role requires its right-side status marker and outgoing body alignment. This is an observed layout profile, not a general semantic sender classifier. Groups, media and other layouts are unsupported; the selected demo must remain one-to-one. Version changes are rejected before text is read.

WhatsAppTextReader traverses without text first, then reads only planned message fields (≤1000chars), timestamps (≤32) and header identity (≤128). It never reads composer drafts, content descriptions or contact lists. A second structural traversal must match the first. The header is salted into a capture-session identity. Turn keys hash identity/role/text/time/occurrence; identical repeated windows are suppressed. These keys do not establish stable message identities across arbitrary scrolling or duplicate-name conversations; later rolling context must account for those limits.

Current app behavior is an explicitly armed, one-minute-expiring single inspection. Two matching consecutive reads verify repeat suppression; changing/uncertain reads become unavailable. Raw messages remain in RAM. The automatically saved whatsapp-parser-report.json contains only status, ordered roles, composer coordinates and repeat-suppression result. It contains neither text nor identity. Pause/revoke/sign out/service destruction clear captured state/report. No Internet permission or backend transfer exists.

Actual-device fixture tests use the real structural asset with invented text. They verify eight complete rows (one local/seven remote in the latest bounded window), composer, clipped-row/draft exclusion, repeat dedup, changed content, unknown group markers and missing sender evidence, text-free report and pause cleanup. Actual host text parsing remains a separate manual/device acceptance gate.
