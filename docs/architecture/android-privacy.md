# Selected-chat privacy boundaries

Base inspection consent and USB-processing consent are separate, versioned and unchecked by default. Every read requires resumed base consent and the exact allowlisted package/build. A live session must be explicitly started, expires if no supported conversation is selected within one minute, and binds to one salted identity and application window. It ends on departure, pause, revoke, interruption, service destruction or persistent unsupported layout. A transient1500ms retry reads no text until the structural read plan succeeds. No host action or message sending is implemented.

Only approved header/message/date fields are read. The header is hashed with an ephemeral per-service salt, retained only as opaque session identity. Dates create stable turn keys. Neither is transmitted. Composer drafts, content descriptions, contacts, media, quoted replies/reactions and unrelated apps are excluded. At most eight complete visible text messages,1000 characters each, replace earlier context; only their LOCAL/REMOTE role and text go to the fixed USB loopback endpoint.

For active live sessions the reader first reads only the bounded header and compares its opaque hash/application window with the selected session. A mismatch prevents all message/date reads. It checks structure throughout traversal and verifies the header remains unchanged before accepting the snapshot; two complete reads must agree. This is an additional defense beyond navigation-event/session invalidation.

The Android worker has one running request and one pending replacement. Pause clears queued work and invalidates all callbacks. A request already sent can finish in memory within its timeout; it cannot be recalled. Request byte arrays are zeroed after use, but Java strings/model internals are reclaimed by normal garbage collection, not guaranteed secure erasure. Backend inference uses local model artifacts, one concurrent request, bounded input/output, no message repositories and no raw normal logs. Models are loaded once; context is per request. The frontend legacy demo may retain its own fictional repository state; the overlay endpoint does not use it.

Android backups/device transfer are disabled. No chat text is persisted. Optional debug structural export contains resource IDs/classes/bounds only; parser reports contain status/roles/composer, with no text or identities. Settings → Clear inspection data and pause clears these files and RAM probes/live session while retaining consent. Remove USB connection and pause additionally removes this app's private token and revokes live processing. Device account credentials remain in Keystore-protected app storage; account sign-out is separate. Android app-data deletion/uninstall removes all local app data. The PC token/logs are developer-controlled under ignored temp/ and do not contain chat text; removing the phone config does not delete the PC token.

For this developer demo, plaintext HTTP is restricted to127.0.0.1 in the debug APK and forwarded over authorized USB. The backend launcher binds127.0.0.1. No public hosting or production transport is provided. Release cleartext remains disabled. Adding an app or network destination requires a new reviewed adapter/transport policy and appropriate disclosure/consent; registry entries alone cannot broaden capture.
