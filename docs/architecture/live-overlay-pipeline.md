# Live selected-chat analysis (USB demo)

Current consumer behavior (Phase45): one home ON/OFF controller owns both overlays. A new affirmative automatic-visible-chat disclosure, resumed local consent, verified model and live foreground companion owner are all required. ON processes verified foreground WhatsApp chats without an arm timer; the first header gate selects a new opaque identity and invalidates the prior generation before body reads. A second observation must match it. Other-app/lock departures clear capture, and supported re-entry can resume while ON. OFF, notification OFF, task removal and owner loss invalidate results and remove overlays. Cold process creation clears stale ON. The selected flow below remains for explicit developer and optional rated-feedback sessions; automatic mode never contributes to the learning buffer.

Phase32 added a separate live-processing opt-in. The earlier consentVersion2 allowed local test inspection only and could not enable network processing. Live consent is versioned separately, unchecked by default, and requires base consent plus resumed state. Starting a session arms one selected fictional chat for one minute; the session binds to its opaque conversation key. Leaving, pausing, revoking or changing conversation invalidates pending results and ends selection. A window change is accepted only after verifying the same selected header identity before reading message text. A new session must be explicitly started after departure. The current consumer engine runs on-device; the USB path below remains a developer option.

The adapter still requires its documented exact WhatsApp build and unambiguous visible plain-text layout. It reads at most eight complete turns of at most1000 characters, compares two immediate observations, and rejects uncertain changes. No draft, contact list, media content or content description is read. The rolling window replaces earlier context; it does not accumulate history. The worker allows one running request and at most one pending replacement, deduplicates unchanged windows, and ignores obsolete results. In-flight text can remain in memory until the bounded request finishes; an already-sent request cannot be recalled by pause.

Transport is deliberately limited to this developer demo: the debug APK permits cleartext only to127.0.0.1, forwarded by `adb reverse tcp:8080 tcp:8080` to the connected computer. `files/overlay-connection.json` in TEMPER's private app storage holds a random64-hex bearer token. It is separate from consent and cannot enable capture. No token, hostname supplied by a chat, or raw message is logged. Redirects are disabled; requests recheck consent/session before writing; responses are bounded to64KiB and strictly validate eight scores, known state/direction and short text. Release cleartext remains disabled.

Restart the loopback backend with `scripts/start-overlay-backend.ps1` after building the backend JAR. Its optional JavaHome/ModelsRoot parameters locate existing installations; it retains the ignored private token in temp/overlay-connection.json, verifies model files, refuses to replace an existing port8080 listener, and starts Java hidden using a temp/ runtime copy so the source build output remains unlocked. ADB forwarding must be restored after device/ADB restart using `scripts/configure-overlay-usb.ps1`. Restoring backend/USB transport does not change consent or start chat capture.

`POST /api/overlay/analyze` requires a configured token of at least32 characters, defaults disabled without it, caps input at64KiB/eight turns, and admits only one inference request at a time. Request roles/text stay in local memory. `LiveOverlayService` uses existing emotion/sentiment/sarcasm/toxicity models, lexical indicators, conflict engine, trajectory engine and compact mapper directly, without conversation/message/analysis repositories. Fixture-derived conflict channels fail unavailable. Output contains only available, character, two short summaries, eight spectrum values, trajectory and evidence strength; no source text, identities, message IDs or detailed matched cues. Responses use no-store.

The visible window needs at least three complete turns and both local and remote roles. Unsupported documents, quotes, reactions or ambiguous roles remain unavailable. A composer can still display a neutral shell when analysis is unavailable. Numeric scores are independent model estimates, not mutually exclusive emotion probabilities or proof of feelings.

Phase40 separates overlay per-turn classifier inputs from the legacy web analysis input. Emotion/sentiment/sarcasm/toxicity models now receive only the current speaker's normalized text for each visible turn; the lexical indicators, conflict aggregation and trajectory retain causal conversation history. The latest REMOTE turn supplies the eight spectrum bars, so LOCAL language cannot contaminate them. The generated role-control regression previously reproduced44.1% remote anger/32.2% remote happiness from LOCAL text alone; fixed spectra are identical across LOCAL-tone variants. See [dummy spectrum checks](../demo/EMOTIONAL-SPECTRUM-CHECK.md) for English/Hinglish results and unresolved language/model limits.

Date separators in the observed WhatsApp build are TextView leaf metadata and never enter the text-read plan. Rows clipped at either list edge are excluded before their content type is checked, so a partial image at an edge does not reject otherwise complete text turns. Fully visible unsupported media still rejects analysis. The text-free 66-node device fixture covers date separators, call summary metadata, eight complete text turns with four of each role, and clipped rows at both edges; all test text is generated separately.

Scroll events are subscribed explicitly and debounced for450ms. As of Phase44, unreadable/changing layouts invalidate pending analysis and display no scores while retaining the selected opaque identity. Recovery uses short initial retries followed by slower checks while the supported application remains foreground; a readable snapshot restores analysis automatically. Keyboard/composer movement no longer ends selection. Explicit stop, departure, pause, revocation or service shutdown clears the retry state and selection. Unsupported messages are never analyzed. The on-device model session can stay loaded during temporary suspension without retaining earlier chat text.

The active analysis companion now supports dragging, with a saved local normalized position. Its initial location follows the composer until the user moves it. Subsequent keyboard/layout changes clamp the preferred position inside the visible chat area without overwriting it. Taps toggle the compact panel, while drags/canceled gestures do not open it. Popup placement is calculated around the current companion position.

A non-chat/unsupported WhatsApp screen can wait without reading messages and resume on returning to the same selected chat. A different verified chat identity, a confirmed other foreground application or lock ends selection. This preserves the selected-chat permission boundary while avoiding keyboard-driven restarts.

Verification:48 backend tests with all five local model integrations enabled pass; Android build/lint and physical-device consent/session/parser/response suite pass. Actual endpoint requests with generated positive/angry conversations produce distinct model scores. A separate generated-text Android transport check reaches the real backend over USB, blocks stopped/revoked requests and restores original consent afterward. The user confirmed real selected-WhatsApp numeric analysis, keyboard movement/input usability and refresh after scrolling. The final installed0.39.0 build separately reported "Model analysis updated" in TEMPER's own status page, and its character/panel windows were verified visible in the selected chat. See phase38/39 handoffs for evidence and support limits.

## Phase 46 on-phone context and runtime

The current phone engine uses a trained bounded context head for direction, retaining remote-only emotion bars. Work uses a non-postponable event deadline and a single worker/pending slot. Trailing outgoing turns do not cancel the target incoming estimate. Up to eight hashed score entries are cleared at identity/departure; public model assets may remain for 60 seconds or until OFF. Prewarming reads only public assets. Compact BPE tables and linear child indexing reduce allocation and repeated work. See [context and performance](../release/CONTEXT-AND-PERFORMANCE.md) for measured costs, synthetic evaluation limits and complexity.
