# Accessibility consent — detection-only build
Open TEMPER → Accessibility and consent. Read the disclosure, check the opt-in and press Save consent. Acceptance leaves TEMPER paused. Open Android Accessibility settings, select TEMPER under downloaded/installed services and enable it yourself. Return to TEMPER and press Resume TEMPER. Open WhatsApp, return to TEMPER and press Refresh status to see whether a supported package event was recently received. This status does not mean a conversation was parsed.

Pause stops detection immediately. Revoke consent and disable removes consent, restores pause and requests Android to disable the connected service. The system settings toggle is independent: if it remains enabled, turn it off in Android Accessibility settings. A service connected without current consent disables itself. Sign out also pauses TEMPER.

Historical version1 consent permitted package detection only. Current version2 invalidates that earlier opt-in and discloses selected fictional test-chat inspection, future bounded local message parsing and no server transfer. The current implementation still reads no text: a user-armed one-shot probe traverses only visible WhatsApp structural nodes, recording IDs/classes/bounds and composer editability. It never reads event text, node text or content descriptions. The service is protected by BIND_ACCESSIBILITY_SERVICE and filtered to com.whatsapp events. It does not perform gestures, click or send. No Internet permission or overlay drawing exists. Server transfer requires a separate future opt-in.

For calibration, prepare a one-to-one fictional chat with visible sent and received messages. Save the new consent, manually enable the Android service, resume and tap Arm next fictional chat layout. Within one minute open that chat, return to TEMPER, press Refresh status and Export text-free layout metadata. The export is a private debug JSON file containing structural metadata only. Pause/revoke/reset/sign out clear it and the in-memory observation. Arming again removes any previous export. This output supports parser calibration and is not proof that messages/roles have been parsed.

Tests exercise default/stale consent, pause, exact supported-package boundaries, UI opt-in and revoke, plus existing account/foundation checks. One-shot probe/composer gating, text-free export and pause/revocation cleanup also pass on device. Actual package detection was confirmed by the user. Native instrumentation restarting the target can remove system service activation, so enable again after test runs; simulated policy tests are not evidence of real service delivery.

Platform references: [AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService), [AccessibilityServiceInfo](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo).
